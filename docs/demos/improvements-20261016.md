## GitHub 读取与 CI 证据

- PR 和发布工作流使用 GitHub `head_sha` 参数查询，最多读取三页并再次核对返回 SHA。PR 模型上下文最多保留 20 个 CI，截断写入覆盖记录。
- PR 的实时 CI 优先于旧同步缓存；明确失败才判为检查失败，缺少结果或仍在运行保留未知。
- 区分无效凭据、权限拒绝、不可见/不存在资源、日志资源失效和临时链接失效。404 本身不被解释成过期；签名链接失效只重新取一次，权限失败不自动重试。
- CI job/失败步骤保存独立证据和 evidence_id；日志不可读时展示可确认的失败步骤及权限诊断，根因仍保留 unknown。
- 添加仓库范围的候选列表、同提交 CI 列表、读取诊断及运行证据接口。所有接口沿用登录和仓库成员校验，诊断 POST 保留 Origin/CSRF 校验。

真实只读验证结果存于 `var/github-evidence-verification.json`：仓库和 Actions 可读；当前匿名凭据下，job 日志返回 GITHUB_PERMISSION_DENIED。PR #16 的提交查询结果为 0 个匹配，查询未截断。没有把真实缺失包装成成功。

参考：[GitHub workflow runs](https://docs.github.com/en/rest/actions/workflow-runs)、[GitHub workflow jobs](https://docs.github.com/en/rest/actions/workflow-jobs)。日志签名链接有效期短，读取列表所需能力与下载日志的能力应分别验证。
