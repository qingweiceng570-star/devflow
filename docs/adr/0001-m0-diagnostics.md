# ADR 0001：M0 诊断与业务运行的边界

状态：采用，2026-10-08。

M0 交付身份、模型接口、工具循环与可运行环境。能力探测只读取人工构造的样例，不连接真实仓库，不生成业务审查结论。

能力探测是单实例、最多 60 秒的显式诊断请求，保存成功或失败记录。它不是业务 Run，也没有后台恢复。客户端断线后可从最近记录确认结果，不应盲目连续点击。M1/M2 的同步和研发分析必须进入持久化 Job/Run，不沿用该同步端点。

模型配置使用 OpenAI 兼容 Chat Completions，地址、模型与密钥仅在服务器读取。工具和结构化输出不支持时返回兼容性错误，不自动换成离线模式。fixture 是用户显式选择的协议回放，UI 与记录标明未验证真实模型。

前端使用显式 Next.js Route Handler 转发有界 JSON。固定服务端目标，只允许已定义路径字符和必要 Cookie/Origin/CSRF 头，重定向不自动跟随，超时受控。M0 不支持大文件上传和 SSE；M2 接入流式事件时另加流式响应、心跳、断线恢复验证，不能把现有缓冲逻辑直接用于 SSE。

M0 Worker 仅提供数据库心跳，业务队列在 M1 接入。登录限流为单 API 进程内的限流，当前部署保持单实例；扩容前改为共享状态。

首批通用 Schema 是领域契约的可验证子集。假设、行动项、完整 locator 与持久化 Run/Evidence 在相应阶段补齐，并更新导出契约；不以这些类型存在声称功能已完成。
