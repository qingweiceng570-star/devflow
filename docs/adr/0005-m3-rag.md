# ADR 0005：M3 知识库与检索的实现选择

状态：采用，2026-10-09。

M3 交付文档接入、结构感知切分、BM25+向量混合检索（RRF）、索引代与 Outbox 一致性、召回测试页与 `search_knowledge` 工具。以下为关键实现决策。

## 检索实现

- **BM25 自实现**（`rag/bm25_store.py`，k1=1.5/b=0.75）：完全掌握分词与打分；索引按 (repo, generation) 落盘为不可变 JSON 工件（`var/indexes/<repo>/<generation>/bm25.json`），带 `tokenizer_version`，加载时校验版本不匹配即拒绝。
- **分词器冻结为 `zh-en.v1`**（`rag/tokenizer.py`）：英文小写、保留完整标识符并补充 snake_case/camelCase 拆词；中文连续汉字 bigram；索引与查询共用同一实现。评测前不预设其优于其他分词器（README 13.2 的保留态度）。
- **切分器为 `structure.v1`**（`rag/chunker.py`）：按标题/段落/列表/围栏代码块解析；标题路径与行区间随块保存；目标 600 / 上限 900 / 重叠 ≤80 token（chars/2 估算，estimator 版本随 manifest 记录）；超长代码块按行切分并继承标题；重叠只在放得下时添加，保证不超过上限。
- **向量通道是可选项**：`pymilvus` 是 `knowledge` 依赖组（`uv sync --group knowledge`），Milvus 在 compose `knowledge` profile（etcd+minio+milvus standalone）。缺依赖、URI 未配置或服务不可达 → 该通道标记关闭/降级，绝不伪称完整 RAG；双通道都失败才报 `RETRIEVAL_UNAVAILABLE`。集合按维度命名（`devflow_chunks_<dim>`），维度变化即新集合。
- **DB 回查是唯一权威**：每个候选都要通过 PostgreSQL（仓库归属、document.state、generation membership、来源/日期过滤）才能进入结果；删除文档在**下一次重建之前**就已被过滤（验收中现场演示）。召回不足时做一次有界补召。

## 索引代生命周期

- 每次构建是**全量重建**：收集所有 active 文档的当前版本块 → BM25 工件 → 可选向量写入 → membership → 计数校验 → 激活。增量复用（按内容哈希跳过未变块）留作后续优化。
- 激活顺序是显式的两条 UPDATE（先降级旧 active，再激活新代），避免部分唯一索引在 ORM flush 乱序下冲突（验收测试覆盖）。
- 保留 active + 1 个 superseded；更早代的对象目录、membership 与向量行一并回收（向量清理尽力而为）。
- Outbox 行只在构建成功且 `created_at <= build_start` 时置为 processed；构建期间新到的行留给下一轮循环（最多 3 轮），仍积压则 `HandlerRetry(15)`。失败保留 pending，后续任何触发都能补处理。
- 上限：单仓库 50k 块；超限生成 failed 记录并保持旧代可用。

## 上传与文档语义

- 仅 UTF-8 Markdown/纯文本（.md/.markdown/.txt，≤5 MiB）；扩展名/编码/空内容/NUL 分别以 415/400/413 明确拒绝。
- `source_key = upload:<filename>` 去重：同内容重复上传返回 `changed=false` 不产生新版本；内容变化生成新 document_version 与新块（旧版本块保留供历史引用）；删除是 tombstone（version+1，检索立即排除），同内容重新上传可复活。
- 服务端健康检查的就绪版本号改为**从 alembic 迁移文件推导**——连续两个里程碑因手写期望版本号而 503，此坑到此为止。

## 预算预留与工具载荷（验收发现并修复）

- 首次知识问答运行被**误报预算耗尽**：循环预留把 JSON 字符数当 token 1:1 计（真实消耗 2,960 / 30,000）。修复：预留改用共享估算器 chars/2（`context/budgeter.estimate_tokens`）。粗界仍保守（中文约 1.5–2 字符/token），但不再把正常的检索型会话挡在门外。
- `search_knowledge` 模型可见载荷收窄：每块文本 1200 字符、去掉完整 trace（保留 generation、degraded 与通道计数）；完整 trace 只出现在检索 API（召回测试页）。
- 工具瞬时失败（如 git fetch 抖动）按设计返回可重试的稳定错误码，模型可重试或换路径；运行不因此崩溃。
