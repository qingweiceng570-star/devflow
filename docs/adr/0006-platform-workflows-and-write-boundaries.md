# ADR 0006：M4–M7 的持久化、扩展与交付边界

- 状态：已实现
- 日期：2026-10-15

## 决策

1. 采用 LangGraph 编排 Planner、Scheduler、Observer、Synthesis。计划来自服务端默认规则或用户提交的类型化 DAG；发布结论使用保守规则汇总。模型负责具体 PR/Issue/CI 分析，不自行扩大计划权限。缺少同 SHA 的成功 CI、必需检查策略、完整证据时不得建议发布。
2. 以 PostgreSQL `TaskRun` / `WorkflowCheckpoint` 作为恢复日志，不另外维护 LangGraph 原生 checkpoint 数据库。完成节点复用，尚未结束的节点重新调度；无法确认用量的模型调用按预留额度保守结算。配置变化时拒绝跨配置恢复。
3. 模型只能通过工具创建本地未批准草稿。外部写入走独立 Job：版本/哈希批准、服务端开关、仓库白名单、批准人当前角色、远端前置条件和租约全部满足后才发送。结果不明标记 unknown，不自动重发；恢复图不包含外部写入。
4. 项目经验需要人工审批和来源绑定。历史摘要为带序号范围的摘录，不消耗新的模型预算，也不当作新证据。周报从已同步的事件快照计数，人工选择入库时标记 generated。
5. MCP 首版只连接管理员审查过的固定 HTTP 服务，不启动 stdio 进程；白名单工具的仓库参数由服务端注入，定义改变则暂停。Skill 为有界声明式步骤，禁止代码、递归及动态安装。每个 Run 固定扩展版本，停用立即阻止后续调用。
6. 目录按职责合并实现；README 的详细设计目录是逻辑边界，不要求为每个规划文件创建空壳。实际模块位置、功能入口与外部依赖边界维护在平台验收记录中。

## 取舍与验证

这些决策使本地学习版可以复现并审查故障行为，同时减少模型自由规划、额外状态存储和第三方依赖。恢复以业务节点为粒度，不能恢复到模型生成的某个 token。活动统计不声称覆盖 GitHub 全量历史；真实 CI 日志不可读时保留未知。

Milvus/embedding、真实第三方 MCP 与 GitHub 外部写入保持可选配置；本轮验证其适配及失败边界，未声称完成这些服务的真实账号联调。重排模型配置暂为预留，当前使用 RRF，`reranked=false`。

验证覆盖后端 249 项、浏览器 7 项、固定评测 40 项、已授权的三个真实业务分析、独立 Compose 空库安装及备份恢复。详见 [平台验收记录](../demos/platform-acceptance.md)。
